Visualizing the Anisotropy -- Causes & Implications

· The Frequency Dimension Problem:

  · A handful of token-frequency-correlated dimensions dominate the space.

  · Words like "the," "a," "is" push all embeddings toward the same direction.

  · Removing these dominant dimensions signi cantly improves cosine similarity

      quality (Mu & Viswanath, 2018).


· Implication for Sentence Embeddings:

  · Mean pooling inherits the anisotropy problem -- sentence vectors also

      collapse into a cone.


  · The `[CLS]` token was trained for NSP (Next Sentence Prediction), not for

      semantic similarity -- even less useful.

The Computational Bottleneck -- Why Cross-Encoding is Too Slow (Part 2)

· The Bi-Encoder Alternative (What we'll build):

  · Encode each sentence independently: sA = f(A), sB = f(B)

  · Compare with a cheap similarity function: sim(sA, sB) = cos(sA, sB)

  · Complexity: n forward passes + O(n2) dot products (which are trivially

      fast).


  · For n = 10,000: ~50 seconds for encoding + <1 second for all

      comparisons.

    Siamese Networks -- The Core Idea

    · Siamese Networks (Bromley et al., 1993; Chopra et al., 2005):


       · Architecture: Two identical neural networks (same architecture, same weights) processing two

          di erent inputs simultaneously.


       · Weight Sharing: Both branches share the exact same parameters . When we update weights

          during training, both branches update identically.


       · Purpose: Project two inputs into a shared embedding space where distance/similarity is

          semantically meaningful.


    · Formal De nition:


    · Input pair: (xA, xB)  Encoding: eA = f(xA), eB = f(xB)


    · Similarity: sim(eA, eB) = cos(eA, eB) or eA - eB


    · Key: Same function f applied to both inputs.


    · Historical Origin: Signature veri cation (comparing two handwritten signatures). Later: face

       recognition (FaceNet), one-shot learning.

Contrastive Learning -- The General Framework

· Contrastive Learning -- Core Philosophy: Learn an embedding space where positive pairs

   (semantically similar) are close and negative pairs (dissimilar) are far apart. This is a paradigm,
   not a single loss function -- many loss variants implement it.


· The Three Ingredients: (1) Anchor xa -- reference point; (2) Positive xp -- similar to anchor (e.g.,
  paraphrase, entailment); (3) Negative xn -- dissimilar (e.g., random sentence, contradiction).
  Encoder f maps all three to embeddings.


· Loss Objective: Penalize when positive is not closer than negative:
  d( f(xa), f(xp))  d( f(xa), f(xn))


· Three Loss Variants (covered next):

   · 1. Triplet Loss -- explicit anchor/positive/negative triplets.

   · 2. Margin Ranking Loss -- similarity-domain equivalent of Triplet Loss.

   · 3. MNRL / InfoNCE -- in-batch negatives; no explicit negative mining needed.

Triplet Loss -- Mathematical Breakdown

· Triplet Loss (Schro et al., 2015):

   

    triplet = max (0, d(a, p) - d(a, n) + )

   

  where a, p, n = anchor/positive/negative embeddings; d(  ) = Euclidean or cosine distance;
   = margin (typically 0.5­1.0).

· Zero-loss condition: When d(a, p) +   d(a, n) -- positive is closer than negative by at
  least  -- loss = 0, no update. If violated:  > 0  gradient pushes p closer and n further.

· Role of margin : Without it, the model satis es the constraint by a tiny gap (lazy learning).
   enforces a minimum separation; larger   stricter  better geometry but harder

   training.


· Distance function choice: SBERT's triplet experiments use Euclidean distance with  = 1;

   cosine distance also works and is the common choice in modern libraries.

Triplet Loss -- Hard Negative Mining

· The Problem with Random Negatives:

   · Random negatives are usually "easy" (already far from the anchor).

   · This results in  = 0, meaning the model learns nothing (wastes time).


· Hard Negative Mining:

   · Actively select negatives that are close to the anchor to force the model to learn.


· Three Mining Strategies:

   · 1. Easy: d(a, n)  d(a, p) +  (Loss = 0, useless)

   · 2. Hard: d(a, n) < d(a, p) (Large gradient, but can destabilize training)

   · 3. Semi-Hard: d(a, p) < d(a, n) < d(a, p) +  (Best balance of signal and stability)


· FaceNet Strategy: Use semi-hard negatives for stable and e cient training.

Margin Ranking Loss -- A Pairwise Variant

· Margin Ranking Loss (PyTorch: `MarginRankingLoss`):

   

      = max(0, sim(a, n) - sim(a, p) + )

   

     We want: sim(a, p) to be much greater than sim(a, n)


· Comparison with Triplet Loss:


  · Triplet Loss uses distances (minimize positive distance, maximize negative

      distance).


· Margin Ranking Loss uses similarities (maximize positive similarity, minimize

   negative similarity).


· Mathematically equivalent when d = 1 - sim (e.g., cosine distance = 1 - cosine

   similarity).

Training SBERT -- The Complete Training Loop

· Training Procedure:

   · 1. Load pre-trained BERT-base + add mean pooling layer on top.

   · 2. Dataset: SNLI + MultiNLI (~1M pairs)  sample sentence pairs (premise, hypothesis) + label per

       batch.


   · 3. Forward: encode both sentences with shared BERT  pool  apply the objective you chose (Slide

       14). For this NLI phase: concatenate [u; v; |u-v|]  3-way softmax  cross-entropy.


   · 4. Backpropagate through all BERT layers (not just pooling) -- this is what reshapes the embedding

       geometry.


   · 5. Optional Phase 2: ne-tune on STS-b with regression loss for ner similarity calibration.

· Key Hyperparameters: batch 16, lr 2 × 10-5(Adam + warmup), 1 epoch, max seq 128, mean pooling.

· Training Time: ~20 min (NLI phase) + ~5 min (STS ne-tune) on a single V100 GPU.


· Critical Insight: Fine-tuning the full BERT (not frozen) lets the gradient reshape the embedding geometry

   across all 12 layers -- that is exactly what cures anisotropy.


· Modern recipe (2026): AllNLI triplets + MNRL -- di erent objective, better results

Recap -- Why We Use Dot Product in FAISS

· FAISS provides di erent metric types for its index structures:

  · `IndexFlatL2`: Uses L2 (Euclidean) distance.


  · `IndexFlatIP`: Uses Inner Product (Dot Product).


· Recap from Slide 10 & 21: Once we L2-normalize our vectors ourselves (Slide 41 Step 2

   -- don't assume the model did it):


  · Ranking equivalence: Cosine Similarity = Inner Product.

  · We should always choose `IndexFlatIP`!

· Why `IndexFlatIP`?

  · Dot product is a single fast hardware operation -- and the score it returns is the cosine

      similarity ([-1, 1], higher = better). IndexFlatL2 returns a squared distance (lower =
      better), which is harder to read and to threshold.

Exact vs. Approximate Search -- The ANN Tradeo

· Exact Search: Brute-force -- compare against ALL n vectors. Guarantees 100% correct 
  top-k. Time: O(n  d). Impractical for n > 100K.


· ANN Search: Uses indexing to prune the search space. Returns top-k with high recall (>95%). Time:
  empirically sublinear -- roughly O(log n  d) with HNSW on well-behaved data.


· Fundamental Rule: ANN is an accuracy­latency trade-o ; it is not correct to compare speed without

   Recall@k.


· Key ANN Index Types:


Index   Method                 Query Time          Recall  Best For
Flat    Brute-force (exact)                        100%    Small corpus (<100K)
IVF     Cluster partitioning           O(n  d)     ~95%    Large corpus, low memory
HNSW    Graph-based             O( n  d)           ~99%    Most production systems
IVF+PQ  Cluster + compression   O(log n  d)        ~90%    Billion-scale datasets

                               Very fast, low RAM

· FAISS (Facebook AI Similarity Search): GPU-accelerated, supports all index types and combinations.

   Industry standard.


· Practical Guideline: corpus <1M  HNSW (best recall/speed tradeo ); corpus >1B  IVF+PQ

   (memory-constrained).

 HNSW -- The Graph-Based ANN Index (Conceptual Overview)

· Multi-layer Graph (HNSW-Hierarchical Navigable Small World):

   · Top Layers: Sparse "entry points" for fast jumping across the vector space.

   · Bottom Layer (Layer 0): Dense graph containing ALL data points.


· Search Process (Coarse-to-Fine):

   · 1. Enter at the top layer.

   · 2. Greedy Walk to the nearest neighbor in the current layer.

   · 3. Drop Down to the next layer and repeat until Layer 0.


· Performance:

   · Empirical Sublinear Search: HNSW o ers strong empirical sublinear search, but complexity/

      recall depend on graph construction, `efSearch`, data distribution, and dimension; report
      measured Recall@k and latency.


   · Industry Default: Used in Qdrant, Weaviate, and Pinecone due to its 99%+ recall accuracy.

Building a Vector Index -- Step by Step with FAISS

· Step 1 -- Prepare vectors: Encode all documents with your embedding model  shape

   `[n, d]` (e.g., `[100000, 768]`). FAISS requires ` oat32` arrays.


· Step 2 -- L2-normalize (critical): `faiss.normalize_L2(vectors)` -- sets every

   vector to unit length. After this, inner product = cosine similarity. Skipping this step makes
   search dominated by magnitude, not meaning.

   inner-product index in RAM.


· Step 4 -- Add vectors: `index.add(vectors)` inserts all your normalized documents

   into the index. Done -- ready to search.


· Step 5 -- Query: Encode and normalize the query the same way 

   `index.search(query, k=5)` returns two arrays: `D` (similarity scores 
   `[1, k]`) and `I` (document indices `[1, k]`). Use `I` to look up the original documents.

Choosing the Right Metric for Your Use Case

· Metric Selection Decision Guide:

Use Case            Recommended Metric        Reason
Semantic Search     Cosine Similarity         Direction matters, magnitude doesn't
Document Retrieval  Dot Product (after norm)  Same as cosine when normalized; fastest

Image Similarity    Cosine Similarity         CLIP embeddings are directional
Anomaly Detection   L2 Distance               Absolute displacement matters

RAG Retrieval       Cosine Similarity         Standard for SBERT/E5/BGE embeddings

· Practical Recommendation:


· 1. L2-normalize your embeddings.


· 2. Use Inner Product (dot product) for search -- it's the fastest operation.


· 3. This is equivalent to cosine similarity after normalization.


· Common Mistake: Using L2 distance on non-normalized embeddings. Vectors with di erent

   magnitudes will appear dissimilar even if they point in the same direction.

   cone -- no pair ever scores low, so cosine has no room to rank. The cause is
   the training objective: MLM never asks for sentence-level geometry.


· 2. Siamese/Bi-Encoder = The Fix: Share BERT weights to encode sentences

   independently  contrastive loss reshapes the embedding space.


· 3. Mean Pooling > CLS: Averaging (with attention mask) outperforms `[CLS]`

   token for sentence representation.


· 4. Contrastive Loss Drives Geometry: Triplet loss, MNRL, and other

   contrastive objectives explicitly optimize for "similar close, dissimilar far."


· 5. Vector Indexing Enables Scale: FAISS and ANN algorithms make semantic

   search practical over millions of documents -- the foundation for RAG.
