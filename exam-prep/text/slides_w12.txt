   · End-to-End Backprop: Both the generator and query encoder can be trained

The Document Pipeline -- End-to-End Overview

· Pipeline Stages (O ine Phase):

   · 1. Load: PDF, DOCX, HTML, Markdown  raw text strings.

   · 2. Parse: Extract structure -- headings, tables, sections.

   · 3. Chunk: Split into semantically coherent segments.

   · 4. Embed: Each chunk  dense vector v  d.

   · 5. Index: Store `(chunk_text, vector)` pairs in a Vector Store (FAISS, Qdrant, Chroma).


· Critical Design Insight: Every decision in Steps 1­3 determines what information is

   *retrievable* downstream. Garbage in  garbage retrieved.


· Embedding Dimension Typical Values: `d = 384` (MiniLM), `768` (BERT-base), `1536` (text-

   embedding-3-small), `3072` (text-embedding-3-large).

Naive Chunking -- Fixed-Size Character Splitting

· Simplest Strategy: Split every `chunk_size` characters, with `chunk_overlap`

characters of shared context.
    # chunk_size=512, chunk_overlap=64
                                  chunks = [text[i:i+512] for i in range(0, len(text), 512-64)]

· Three Critical Failure Modes:


· 1. Context Fragmentation (Despite Overlap): Overlap patches short splits,

   but fails if the core subject (e.g., document title) is far from the key fact. Chunk

   B gets the fact but loses the premise.


· 2. Mid-Table Cut: Table headers in Chunk A; 

   data rows in Chunk B  orphaned numbers.


· 3. Cross-Section Bleed: Conclusion of Section 3 fused with Introduction of

   Section 4  retrieval confusion.


· Result: High false-positive retrieval rates; LLM receives semantically incoherent

context.                                                                                         7

The Hubness Problem & Anisotropy in Embedding Spaces

· Two Embedding Space Pathologies:


  · 1. Hubness: A few vectors become nearest 

      neighbors for many unrelated queries.


     · RAG Symptom: The same generic chunks 

         repeatedly appear in top-k results.


  · 2. Anisotropy: Embeddings occupy a narrow 

      region instead of spreading uniformly.


     · E ect: Unrelated vectors can receive in ated cosine similarity.


· Diagnose: Inspect mean pairwise cosine and how often each chunk appears in top-k.


· Mitigate: Use retrieval-trained embeddings, normalization, whitening, or hard-

   negative training.

RRF -- Why the Constant k=60 Works

· The k=60 Intuition:


  · Without k: Rank 1 scores 1/1 = 1.0; Rank 2 scores 1/2 = 0.5 -- 50% penalty for one

      position drop is too aggressive.


   · With k=60: Rank 1 scores 1/61  0.01639; Rank 2 scores 1/62  0.01613 -- about a

      1.6% relative decrease, much smoother than k=0.


·  E  ect of k on Score Curve: score(r) =    1  -      1  =  1                   

                                           k+r     k+r+1
                                                             (k + r)(k + r + 1)

   · Small k  steep early dropo (aggressive). Large k  at curve (all ranks treated equally).


· Empirical Default (k = 60): Cormack et al. (2009) xed k = 60 in a pilot study on TREC data

   and never re-tuned it; later practice nds results fairly insensitive across roughly k  [40, 80],

   which is why k = 60 is the standard zero-shot default.


· Practical Rule: Start with k=60, truncate input lists consistently, and tune only if validation

   data shows a bene t.                                                                              23

The Recall-Precision Gap -- Why Re-Ranking Exists

· Retriever Goal: Find a broad candidate set quickly; prioritize recall.

· Reranker Goal: Reorder that set carefully; prioritize precision.

· Bi-Encoder Limit: Query and document are encoded independently.

· Cross-Encoder Bene t: Joint attention captures negation and token-level

   interactions.


· Trade-o : Larger K may improve recall but increases reranking cost.

· Pipeline: Retrieve K candidates, rerank them, then send only top N to the

   LLM.

CLIP Mental Model

· Question: Does CLIP learn composition or mainly visual­text association?

· Relation Test: "A dog chasing a cat" may retrieve animals that are merely

   adjacent.

   negation.


· Takeaway: Test compositional queries instead of assuming semantic

   understanding.

GraphRAG -- Local vs. Global Query Modes

· Local Search (Entity-Focused):

   · Concept: Traverses entities, relationships, and chunks around target entities.

   · Example: "What are the key achievements of Sam Altman?" (1 LLM call, low latency).


· Global Search (Corpus-Wide Map-Reduce):

   · Concept: Answers broad thematic queries across the entire dataset without a xed entity anchor.

   · Example Query: "What are the top 5 emerging technology themes in all 500 reports?"

   · Map Step (Fan-Out): Send query to all Community Summaries in parallel -> each cluster gives an

      intermediate answer (e.g., Cluster 1: Computer Vision, Cluster 2: LLMs).


   · Reduce Step (Fan-In): Aggregate & rank top intermediate answers -> LLM synthesizes into a

      single holistic Global Answer.


· Cost Trade-O : Global search requires signi cantly more LLM calls and tokens than Local search.

Multi-Hop Reasoning with Knowledge Graphs

· Example Multi-Hop Query: "Which companies did executives who worked for OpenAI subsequently found?"


· The Complete 3-Step Graph Execution Flow:


   · Step 1 -- Query Decomposition (LLM / Text-to-Cypher):


       · LLM analyzes question structure -> generates dynamic multi-hop Cypher query (2 hops in this example):

            
                  MATCH (p:PERSON)-[:WORKED_AT]->(:ORG {name:"OpenAI"})
                  MATCH (p)-[:FOUNDED]->(c:COMPANY)
                  RETURN p.name, c.name


   · Step 2 -- Deterministic 2-Hop Traversal (Graph DB): Graph DB executes Cypher query by strictly following stored graph pointers.
       · Hop 1 (Incoming): `(:ORG "OpenAI")` WORKED_AT `(:PERSON)` -> `{Sam Altman, Dario Amodei}`

       · Hop 2 (Outgoing): `(:PERSON)` FOUNDED `(:COMPANY)` -> `{Worldcoin, Anthropic}`


   · Step 3 -- Answer Synthesis (LLM):

       · Retrieved exact sub-graph triples LLM Natural language response.


· Why Vector RAG Fails Here: Cosine similarity retrieves disconnected chunks mentioning "OpenAI" or "executives", or

   "founded companies", but cannot deterministically chain (A -> B -> C) across separate documents.

Act 4 -- The Long-Context Trap

Long Context Does Not Eliminate Retrieval

· The "Just Stu Everything" Temptation: If context is 1M tokens, why bother

   with RAG at all?


· Two Remaining Problems:


· 1. Computational Cost: Standard full attention forms O(N2) pairwise

   scores. Actual deployed cost depends on attention architecture, kernels,
   caching, sparsity, and hardware.


· 2. The "Lost in the Middle" Phenomenon: LLMs have trouble using

   information from the middle of long contexts (Liu et al., 2024).


· Conclusion: Even with million-token contexts, RAG remains valuable for cost

   and attention-quality reasons.

Sliding Window Attention (SWA) -- E cient Long-Context

· Quadratic Bottleneck: Full attention attends to all prior tokens; O(N2)

   compute/memory blows up at long contexts.


· Sliding Window Attention (SWA): Each token 

   attends only to the preceding w tokens (window size).


· Linear Complexity: Reduces computational 
  complexity from O(N2) to O(N  w).


· Fixed KV Cache: Caches only the most recent w tokens per layer via rolling

   bu er.


· The Core Question: If each layer only sees w local tokens, how does the

   model comprehend long documents?

NTK-Aware Interpolation -- A Smarter Scaling

· The Frequency Insight: RoPE frequency bands serve di erent roles:


  · High Frequencies ( large): Encode ne-grained local position (nearby

      words).


  · Low Frequencies ( small): Encode global position (document structure).

· Linear Scaling Flaw: Uniformly compressing all frequencies blurs local word

   order.


· NTK-Aware Solution: Non-uniform scaling -- compress low frequencies,

   preserve high frequencies.


· YaRN (Peng et al., 2023): Extends LLaMA-2 from 4K to 128K context with

   ~400 ne-tuning steps (0.1% of pre-training tokens).
